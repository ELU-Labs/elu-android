# 0.2.0 release decision

Date: 2026-10-13. Artifact: `dev.elu:elu-analytics:0.2.0`.

## Decision

Release 0.2.0 for analytics: events, screens, identity, sessions, durable
delivery and feature flags. Session replay stays off at release.

0.2.0 is released on the checks listed below instead of the full release
qualification, which also covers installed-app runs, upgrades, replay privacy
rendering and player playback, and performance overhead. Those checks are
deferred for 0.2.0 only. This release does not claim them, and later versions
still need them or their own decision record.

## Scope

- Only `dev.elu:elu-analytics` is published. The optional
  `dev.elu:elu-analytics-compose` module stays in this repository and is not
  published.
- The replay code ships in the artifact, but ELU's service configuration does
  not enable native replay for Android installations at release. Replay stays
  off until it is qualified and enabled separately.
- 0.2.0 starts a fresh installation. It does not import identity, consent,
  events or replay stored by 0.1.0.

## Required before publication

1. The release commit is reviewed and merged to `main`, and its CI run on
   `main` passes every job: unit tests, lint, instrumentation tests on the
   API 23, 29, 35 and 36 emulators, the minified consumer apps run on each of
   those emulators, the public API snapshot, brand and legal artifact scans,
   local distribution checks, the coordinate-only consumer builds (R8 full
   mode with compileSdk 36 and 34, OkHttp 5, Java only, Kotlin 2.0 and
   Compose) and the historical 0.1.0 consumer build.
2. A consumer app built with the core AAR from that CI run is checked end to
   end against the ELU service, with replay off: configuration fetch, custom
   events with device and app context, screens, identify and person
   properties, feature flags, and delivery after a service outage and an app
   restart, all read back from ELU's event store. The signed tag message
   records the outcome.
3. An annotated OpenPGP-signed tag `0.2.0` from a trusted release key, with the
   trailers listed in [release/README.md](../README.md), names that CI run and
   that AAR's SHA-256.
4. The release workflow passes as a dry run, then runs for real. It rebuilds
   the AAR byte for byte and uploads only the core artifact, without releasing
   it. A maintainer checks the deployment in the Central Portal and clicks
   Publish.

## Release notes must say

- Session replay is not yet available for Android. Use the site key of a
  project set up for Android: a key from a project with iOS replay enabled can
  start replay capture in an Android app.
- The Compose add-on is not published.
- 0.2.0 does not import data stored by 0.1.0.
- Which checks were deferred, with a link to this record.
